## C. 新事实源结构

```text
backend/data/skills/
  manifest.json
  skills-001-050.json
  skills-051-100.json
  skills-101-150.json
  skills-151-200.json
  skills-201-250.json
  skills-251-300.json
  skills-301-332.json
```

每张对象保存用户要求的全部 **19 个内容字段**，中文 UTF-8；不保存 id、created_at 或用户数据。长期内容键使用稳定且不可随意改号的 **week_number**；display_order 仅表示主线顺序，skill_name 不作唯一键。

`tags` 是唯一标签数组来源。写入适配器从该数组同时生成 skills.tags 的 JSON 和 skill_tags 行；仓库不维护第二份 skill_tags 清单。运行库 ID 由数据库分配，按插入结果关联标签，不要求 id 等于 week_number。

`backend/seed.js` 已缩减为 JSON 加载与恢复命令兼容适配器，不再携带百万字节内容数组。历史 migration 仍通过它读取同一 JSON 内容，仍只补原有批次的缺失周次，**没有新增将 255—332 自动写入生产的启动迁移**。

## D. 校验与恢复工具

根目录和 backend 目录均可执行：

| 命令 | 行为 |
| --- | --- |
| npm run validate:skills | 只读检查 UTF-8/JSON、必填字段、连续周次、重复周次/名称、合法标签及逐张数量、52 个连续唯一 display_order、分类统计、音频 URL 格式 |
| npm run compare:skills -- --snapshot /path/export.json | 比对仓库与明确提供的生产只读快照，比较全部 19 个字段及独立 skill_tags |
| npm run compare:skills -- --db /path/database.db | 以 readonly + query_only 直接读取明确指定的 SQLite，不导入 db.js，不读取 DB_PATH 默认值，不创建缺失数据库 |
| npm run export:skills -- --db /path/database.db | 同样只读，stdout 只输出 Skill 内容白名单与标签，不输出其他数据表 |
| npm run restore:skills -- --db /local/path.db | 默认只读预览；--apply 仅在本地补缺失卡片，--create 明确创建缺失的内容表 |
| npm run rehearse:skills | 只在新建的本机临时目录演练恢复；不接受目标库路径；在 Railway 环境拒绝运行 |
| npm run test:skills-source | 校验器与只读边界回归测试 |

compare 退出码：0 无差异；1 存在差异；2 输入/结构错误。只读 compare/export 没有 --apply、--fix、--sync 或覆盖数据库选项。独立 restore 默认只预览，显式 --apply 才能在本地补缺失周次，不允许覆盖已有行；不生成激活码，不导入 db.js，不影响业务表。重名暂作警告，不自动改名。历史允许为空的 key_question、growth_friction_ending、insight_audio_url 保留空值并报告；字段键缺失属于错误。
