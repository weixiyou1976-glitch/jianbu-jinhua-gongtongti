# 第225—230周增量迁移

## 生效方式

部署包含本次改动的后端代码后，沿用现有 `npm start` 启动流程。`db.js` 完成现有表结构初始化后自动执行本批迁移，无需重新 seed 已有数据库。

- 内容只维护在 `seed.js` 数组末尾，迁移导入同一份对象。
- 导入 `seed.js` 不会连接数据库、写入完整种子或生成测试激活码；直接执行 `node seed.js` 保留原有 CLI 行为。
- 非空库只检查第225—230周，按 `week_number` 判断存在性。已有周次整条跳过，包括已有标签、状态和音频；不覆盖后台编辑的内容。
- 缺失的 Skill 使用 SQLite 自增 ID，标签使用实际 `lastInsertRowid` 关联，不假设 ID 等于周次。
- 六张 Skill 和标签在同一个 `BEGIN IMMEDIATE` 事务中写入。任一步失败整体回滚；并发迁移取得写锁后再检查，防止重复插入。
- 空库不执行本批增量插入，仍通过原有 `node seed.js` 完整写入1—230周，避免破坏空库判断。
- 没有新增或删除数据库字段，没有删除、更新、重建已有 Skill，没有改动业务路由或前端。

## 数据库确认

在后端目录、实际部署环境执行以下只读查询。它不导入 `db.js`，因此检查本身不会触发迁移，也不会在路径错误时创建空库。

```bash
node <<'JS'
require('dotenv').config();
const Database = require('better-sqlite3');
const db = new Database(process.env.DB_PATH || './data/jianbu.db', {
  readonly: true,
  fileMustExist: true,
});
console.table(db.prepare(`
  SELECT week_number, COUNT(*) AS skill_count
  FROM skills WHERE week_number BETWEEN 225 AND 230
  GROUP BY week_number ORDER BY week_number
`).all());
console.table(db.prepare(`
  SELECT s.id, s.week_number, s.skill_name, s.status,
    COUNT(st.tag) AS tag_count, COUNT(DISTINCT st.tag) AS distinct_tag_count
  FROM skills s LEFT JOIN skill_tags st ON st.skill_id = s.id
  WHERE s.week_number BETWEEN 225 AND 230
  GROUP BY s.id ORDER BY s.week_number
`).all());
db.close();
JS
```

正常新增的结果：225—230各一行、`skill_count` 均为1；六个名称依次为信念链追踪、信念行为化、机会雷达、仪式开关、信念反证、可控信念；状态为 `published`，每张8个标签且无重复。若迁移前已经存在某周，自定义内容保持原样，应单独核对而不是覆盖。

启动日志只在实际新增时输出 `Skill 225—230 增量迁移：新增 N 张`。再次启动不输出新增日志是正常的；以只读查询为准。

前端入口为 `/skills`，实际后端接口为 `/api/skills`。登录后可按 `?week=225` 等查询；详情使用返回的 `id`，不能把周次当作数据库 ID。
